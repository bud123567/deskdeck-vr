# Security boundary

The Mac companion is the only component allowed to capture or inject input. Browser code has no macOS privileges. macOS TCC controls Screen Recording and Accessibility. No shell strings, AppleScript programs or arbitrary executable/file paths are accepted from the client. App IDs and shortcuts are explicit allowlists; numeric pointer/scroll values are bounded and non-finite values rejected. Keyboard/button state is released when the channel disconnects, the peer stops, or the focused desktop loses focus.

The single-host service is trusted infrastructure. HTTPS/WSS certificates must be trusted normally; no trust-all delegate exists. The native host authenticates using a 256-bit bootstrap secret provisioned locally via a 0600 file, then saved in Keychain. The server's private data directory is 0700; host secret is necessarily available to its owner/server. Rotate a compromised bootstrap by stopping the service, replacing its config and reimporting on the host. Do not place `.data` in a web root or source control.

Six-digit codes expire after two minutes, are cryptographically generated, rate limited per socket address and globally, consumed on a pairing request, and require explicit approval on the Mac. Origin validation applies to mutations and browser socket upgrades. Tokens are random, stored only as hashes on the server, expire after 30 days and are HttpOnly / Secure / SameSite=Strict in production. They are not stored in localStorage or query strings. Native credentials remain in Keychain. Revocation terminates sockets and sessions immediately; one browser session is active at a time. Signaling messages require the current session ID and are bounded in size.

Loopback-only HTTP development deliberately omits Secure cookies. Production requires direct TLS or explicit `TLS_TERMINATION=loopback` with an HTTPS `PUBLIC_ORIGIN`. The latter only binds to `127.0.0.1`, behind a trusted local HTTPS tunnel/proxy; browser cookies remain Secure and origin validation uses the public HTTPS origin. Native host authentication can use the private loopback WebSocket connection. No proxy headers are trusted. Proxied clients share the loopback source's rate limit, in addition to the global limit. The API-only CLI flag is for integration testing; it removes frontend serving and does not bypass any authentication. Unpaired status responses do not reveal the Mac's hostname.

WebRTC encrypts both media and data. The browser prioritizes H.264, but codec negotiation and hardware support are verified separately. No TURN credentials, remote access, public registration, arbitrary file access or automatic clipboard monitoring are implemented. The browser dashboard shows actual transport metrics; RTT is not one-way or motion-to-photon latency.

Limits: local administrator compromise, a malicious trusted headset, an XSS in the trusted origin, or compromise of the signaling service can defeat these boundaries. This is development software, not an independently audited remote access product. Certificate renewal, log/backup retention, signing/notarization, resource abuse under sustained authorized traffic, device-specific performance and privacy review remain release work.
